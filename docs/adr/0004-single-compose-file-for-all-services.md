# 0004. サーバーで動かす全サービスを1つの compose ファイルにまとめる

- ステータス: 採用
- 日付: 2026-10-12

## コンテキスト

ADR 0002 ではサービスごとに `~/services/<名前>/compose.yml` を置くと決めた。実際には compose ファイルが5か所に分かれ、全体の状態確認や起動・停止をサービスの数だけ行う必要がある。

## 決定

全サービスを `~/services/compose.yml` の1ファイル（1つの compose プロジェクト `services`）に書く。テンプレートは mini-pc-setup の `templates/services/compose.yml.j2` の1つ。

```
~/services/
  compose.yml          全サービスの定義
  <サービス名>/
    secrets/           1キー1ファイル
    data/              1000:1000。make deploy のたびに手元へバックアップ
```

秘密情報・データ・ポートの扱いは ADR 0002 のまま変えない。

## 結果

- `docker compose ps` などの操作が1回で全サービスに効く
- 1サービスの書き間違いで全サービスのデプロイが止まる。ファイルを分けて `include:` で読み込んでも、compose は全体を1つの設定として読むため同じ
- コンテナ名が `services-<サービス名>-1` になる。watchtower の監視対象名を合わせる

## 検討した代替案

- **サービスごとに別プロジェクト（ADR 0002 のまま）**: 失敗が他へ波及しないが、操作がサービスの数だけ要るため却下
- **入口のファイルから `include:` で各サービスのファイルを読む**: 操作は1回で済み、ファイルはサービスごとに分かれて見やすい。失敗の波及は1ファイルと変わらない。全体を1枚で見渡せるほうを選んだ
