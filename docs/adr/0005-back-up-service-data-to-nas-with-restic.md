# 0005. サービスのデータを restic で NAS へ毎日バックアップする

- ステータス: 採用
- 日付: 2026-10-25

## コンテキスト

`make deploy` のたびに各サービスの `data/` 全体を手元 PC へコピーしており、写真が増えるほどデプロイが遅くなった。自宅 LAN には Buffalo LS210D（SMB・FTP・AFP 対応、ドライブ1台）がある。

## 決定

mini-pc 上の restic で LS210D の SMB 共有へバックアップする。

- 毎日 3:30 に systemd タイマーで実行し、`make deploy` の最初にも1回実行する（失敗したらデプロイを止める）
- SQLite は `sqlite3 .backup` で複製して渡す
- 世代は日次7・週次4・月次12
- 失敗の通知は当面入れない
- 手元 PC へのコピーはやめる（ADR 0004 の記述を置き換える）

## 結果

- 差分だけ送るのでデプロイが速くなる
- 失敗に気づく手段が無い
- NAS も同じ家にありドライブ1台なので、火災・NAS の故障・mini-pc の乗っ取りでは失われうる
- restic のパスワードを失うと全世代が読めない。正本は `vars/secrets.yml`

## 検討した代替案

- **FTP**: 平文で流れ、restic から直接書けない
- **AFP**: 廃止の方向で、Linux からの対応が弱い
- **rsync で NAS へコピー**: 世代管理と破損の確認を自前で作ることになる
- **NAS 側から取りに行く**: Ansible で管理できず、SQLite の複製も作れない
