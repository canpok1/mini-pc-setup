# 0008. OS と apt のパッケージを unattended-upgrades で毎日自動更新する

- ステータス: 採用
- 日付: 2026-10-27

## コンテキスト

コンテナは watchtower で自動更新している（ADR 0001）が、OS と apt で入れたミドルウェア（Tailscale・Docker など）は手で更新しないと古いまま残る。mini-pc-setup は ansible-pull で自動適用している（ADR 0007）が、main に変更があったときしか動かない。失敗を通知する仕組みは無い。公開直後の更新に不具合があったときに巻き込まれたくない。

## 決定

Ubuntu 標準の unattended-upgrades を Ansible で設定し、毎日 5:00 JST に更新する。

- 対象はセキュリティ更新だけでなく、Ubuntu の通常の更新（`-updates`）と、追加した外部リポジトリ（Tailscale・Docker）も含める
- Ubuntu 公式の更新は、公開から7日たったものだけを入れる。更新の直前に apt の参照先を snapshot.ubuntu.com の「7日前の時点」へ切り替える（`APT::Snapshot`）
- セキュリティ修正（`-security`）は snapshot の対象から外し、翌朝に入れる
- 再起動が必要な更新のときは、更新の直後に自動で再起動する（全コンテナが `restart: unless-stopped` のため自動で戻る）
- 更新の時刻はタイマーで決める。unattended-upgrades の再起動時刻の指定は mini-pc の時計（UTC）で解釈されるため使わない

## 結果

- OS とミドルウェアの更新に手作業が要らない
- 再起動が必要な日は、5:00 過ぎに数分サービスが止まる
- Tailscale と Docker のリポジトリは snapshot に対応していないため、公開後すぐの版が入る
- snapshot.ubuntu.com に繋がらないときは10分おきに取り直す（2026-10-27 の初回実行で 503 が返った）。4回とも失敗した日は Ubuntu 公式の通常の更新を見送り、セキュリティ修正と外部リポジトリの更新だけを入れる（その時点の一覧が無いので、待たずに新しい版が入ることは無い）
- 手で `apt install` したときも7日前の版が入る
- `/etc/apt/sources.list.d/ubuntu.sources` を Ansible が上書きする（ミラーを変えるならテンプレートを変える）
- 失敗の通知は無い。自動デプロイの失敗通知と合わせて別途決める

## 検討した代替案

- **playbook で `apt upgrade` する**: ansible-pull は main に変更があったときしか動かず、定期実行にならない。デプロイの失敗と更新の失敗も混ざる
- **セキュリティ修正も7日待つ**: 設定は単純になるが、公開済みの脆弱性が最大7日残る。セキュリティ修正は変更が小さく、待つ利点が小さい
- **再起動を手で行う**: 失敗の通知が無いため、再起動が必要な状態に気づけず、カーネルの修正が反映されないまま残る
